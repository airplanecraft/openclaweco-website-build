深度体验 Antigravity CLI 总结

2026年5月27日 | 作者: Eric w

深度体验 Antigravity CLI 一周：迈向 Agent-First 时代的利器与进化方向

在深度、高强度使用 Antigravity CLI 接近一周后，我整理了这份关于它的核心优势与未来改进空间的深度总结。作为一名同时拥有多款 AI 编程工具（包括两个 Claude Code Pro 和 Codex）的重度开发者，我将从实际生产力的角度，客观聊聊它的“得与失”。

🌟 核心亮点与优势（👍 值得点赞的地方）

1. 真正的 Agent-First 平台，降维打击传统 CLI

Antigravity CLI 在设计理念上实现了真正的“Agent-First”（智能体优先），这让它在实际编码和多任务协作中的表现，远远超越了上一代的 Gemini CLI。

2. 默认模型 Gemini 3.5 Flash (Medium) 表现惊艳

系统默认搭载的 Gemini 3.5 Flash (Medium) 表现堪称惊艳，在速度、上下文理解和推理能力上，都远远超越了之前的 3.1 Pro 模型，日常编码体验极佳。

3. 多模型生态支持：完美的“降维打击”后备军

持续支持 Claude 3.5 Sonnet / 3.6 Opus 以及 GPT-o4s 等第三方顶级模型，是 Antigravity CLI 的核心王牌。在 Gemini 偶尔遇到瓶颈的棘手场景下，一键切换到第三方模型往往能带来突破性的解决方案。

4. 极致性价比：99.99 Ultra 订阅档位的“省钱美学”

新推出的 $99.99 Ultra 订阅档位简直是开发者的福音！此前我一直订阅的是 $249.99 档位，但日常额度根本用不完。再加上我同时订阅了两个 Claude Code Pro（共 $40）和 Codex，Ultra 档位的推出直接帮我每月省下了 150 美刀的刚性开支，性价比拉满。

5. 灵活的 Workspace 管理：支持 /add-dir

虽然 Antigravity CLI 是从特定目录启动的，但它像 Claude Code 一样引入了类似工作区的概念。通过 /add-dir 命令，开发者可以轻松扩展上下文空间，非常契合大型复杂项目的开发流。

6. 丰富的斜杠命令（Slash Commands）生态

支持极其丰富的命令矩阵，如 /rewind （回滚）、 /fast （快速模式）、 /btw 、 /artifact 、 /agents 、 /permissions 、 /config 、 /planning 等，赋予了命令行极高的可控性与深度定制空间。

⚠️ 痛点与待优化空间（💬 期待加强的地方）

1. 剪贴板图片支持缺失（无法直接复制图片）

• 现状：目前不支持直接通过 Command + V 粘贴剪贴板中的图片，必须手动指定本地图片的绝对或相对路径。 • 吐槽：在 UI 调试和 bug 反馈时极其不方便，这方面 Claude Code 的快捷粘贴体验要好得多，希望尽快跟进。

2. 模式切换交互略显繁琐

• 现状：虽然引入了 /planning 和 /fast 模式来适应不同复杂度的任务，但交互体验有些混乱。 • 建议：希望引入类似 Claude Code 中 Shift + Tab 的快捷键设计，实现无缝、直观的模式切换。

3. 插件生态（Plugin）仍需完善

• 现状：目前的生态刚起步，缺乏像 Claude Code 那样丰富的社区插件（例如 ccstatusline 、 claude-mem 、 claude-hud 等）。 • 展望：期待未来能有更开放的 API，允许开发者定制专属的 CLI 状态栏和辅助工具。

4. Token 消耗速度较快

• 相比于 3.1 Pro，Antigravity CLI 的 Token 消耗速度大约快了 3 倍。对于重度开发者来说，额度流逝的速度非常明显，需要更精细的上下文控制机制。

5. 基础工具链（如 Diff 展现）有待精细化

• 部分内置工具的体验还不够极致。例如代码变更的 diff 视图不够直观和美观，视觉上的易读性还有很大的提升空间。
