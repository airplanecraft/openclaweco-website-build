天工3.2重磅上线Skywork Tags：让AI Agent直接进入工作群

2026年7月2日|3 分钟阅读
#skywork#enterprise-agent#collaboration-agent#anthropic#llm-interaction

继上周 Anthropic 推出让 Claude 常驻 Slack 频道的 Claude Tags 功能后，前特斯拉 AI 负责人 Karpathy 指出，这标志着大模型交互的第三次范式转变：从网页端、桌面端应用，演进为 AI 成为组织中持久运行、拥有团队完整工具和上下文的“数字化员工”。

为此，昆仑万维在其最新发布的 天工 3.2 升级中，正式推出了 Skywork Tags。该功能直接接入国内外的协作工具，包括 飞书、钉钉、Slack、Discord 和 Telegram。你的团队在哪里沟通，#Skywork 就在哪里“上班”。

过去一年，几乎所有的 AI Agent 产品都面临着极大的用户摩擦：它们要求用户将散落在群聊、文档、表格中的上下文手动“搬迁”到一个全新的工作区中。而 Skywork Tags 采取了相反的策略：不搬迁上下文，而是直接将 Agent 引入现有的团队工作流。只需在日常群聊中 @ 机器人，它就能无缝读取上下文并参与协作。

与传统的单兵 AI 助手不同，Skywork Tags 的核心在于“共享”。同一个频道里只有一个 Skywork 实例。这带来了三个维度的变革：首先是透明度，Agent 的任务处理进度对全员可见，避免了信息黑盒；其次是可异步接力，团队成员可以无缝承接 Agent 推进的任务；最后是自我演进，由于长期在群组中沉淀上下文，它会变得越来越聪明。

开发团队通过数月的内部对照实验验证了这一模式的优越性。他们将“个人定制版”Agent 与“百人团队共享版”进行对比。起初，个人版因针对性调教显得更顺手；但在两三周后，共享版在吸收了产品、研发、运营等多角色、多角度的丰富语境后，能力实现反超，最终团队彻底放弃了个人版，全面转向共享的 AI 协同模式。

AgentUpdate 深度解析

过去，行业普遍将 AI Agent 视为个人的“Copilot”，而 Skywork Tags 和 Claude Tags 的出现，宣告了 AI 正式跨入“协作时代”。这种“不改变用户工作习惯、直接接入现有 IM 生态”的降维打击方式，比搭建全新的 Agent 操作系统更具落地可行性。从长远来看，未来的组织架构将是“人+Agent”混编的。谁能最先解决多模态上下文的长期记忆和团队共识的动态更新，谁就能在企业级 AI 市场占据主导地位。Skywork 共享模式的成功证明，群体智慧不仅能喂养人类团队，更是让 AI 摆脱泛化能力不足、实现场景深耕的最短路径。
