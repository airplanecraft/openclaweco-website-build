微软停用Claude Code：揭示AI Agent时代企业算不起的Token账

2026年5月25日 | 3 分钟阅读
#claude#github copilot#mcp#ai agent

去年12月，微软向成千上万名工程师、产品经理和设计师开放了使用 Anthropic 命令行编码 Agent 工具 #Claude Code 的权限，并由公司买单。

到了春季，这款工具的普及范围已经远远超出了工程部门，甚至渗透到了那些在传统企业软件时代需要等待数年才能获得席位的非技术角色中。在微软内部，这次推广被定性为一次学习实践；但在外界看来，这释放了一个更为直接的信号：这家全球最大的软件巨头，在拥有自主基础模型和编码助手的情况下，竟然付费让员工使用竞争对手的产品。

然而仅仅六个月后，这场实验正在走向终结。根据 Windows Central 等媒体紧跟 The Verge 独家报道后的后续消息，微软正在取消其“体验与设备”部门（Experiences and Devices group，负责构建 Windows、Microsoft 365、Outlook、Teams 和 Surface 的部门）中绝大多数直接的 Claude Code 许可。

受影响的工程师已被告知，必须在 6 月 30 日（微软财政年度的最后一天）之前迁移到 #GitHub Copilot CLI。官方给出的理由是“工具链统一”，而未明说的原因则藏在财务账单里。

微软对 Claude Code 的撤退释放了一个极其可信的信号：在当前的 Token 价格下，企业级 AI 编码的单位经济学（Unit Economics）根本行不通。这并不是因为工具不好，恰恰相反，正是因为它们太好用了，导致工程师们无时无刻不在使用，而这种高频使用彻底击穿了财务预算。

最清晰的证据来自 Uber——一家没有微软那样雄厚财务缓冲资金的公司。Uber 首席技术官 Praveen Neppalli Naga 在今年 4 月透露，该公司在短短四个月内就烧光了原本规划到 2026 年的全部 AI 编码预算。

数据显示，到今年 3 月，Uber 内部 5000 名工程师中，Claude Code 的使用率已从 32% 飙升至 84%。部分工程师个人每月在 Token 上的花费在 500 美元到 2000 美元之间。目前，Uber 提交的代码中约有 70% 源自 AI，而在生产环境的后端更新中，约有十分之一是由完全没有人类参与的 Agent 自主交付的。

“我不得不重新制定计划，”Naga 表示，“因为我原本以为足够的预算早已经被彻底耗尽了。”

这句话可以说是整个行业的缩影。企业之所以预测错误，是因为他们试图预测的变量——Token 消耗量，其运作逻辑与财务团队习惯模拟的账号许可（Seats）完全不同。传统的企业软件交易是按用户数量计费的。

而以 Token 定价的交易，则是根据模型“思考”了多少来计算的。Agent 式的编码会让模型进行大量的思考。Agent 运行会持续数小时，生成并行线程，并产生巨大的上下文体积，这与简单的代码自动补全（Autocomplete）有着本质的区别。

AgentUpdate 深度解析

微软停用 Claude Code 并强制向 GitHub Copilot 迁移，不仅是一次工具链的收拢，更宣告了第一代“Agent 经济学”的破产。在传统的 Autocomplete（如 Copilot 早期版本）时代，Token 消耗是线性的、可预测的；而进入以 Claude Code 为代表的 Agentic 时代，AI 开始自主规划、并行调用、反复试错，这导致 Token 消耗呈指数级攀升。Uber 的预算崩溃正是这一技术范式转移的缩影。对于 #AI Agent 生态而言，未来企业级落地的胜负手将不再仅取决于模型的能力（Capability），更取决于“能效比”（Efficiency）以及计费模式的创新。未来我们或许会看到更多类似 MCP（Model Context Protocol）的轻量级端侧协同、混合模型路由（Hybrid Routing）以及企业级“Token 封顶/阶梯式”SaaS 计费方案的出现，否则高昂的运行成本将成为阻碍 Agent 真正走向生产力的最大管辖区。
