Anthropic发布Claude Opus 4.8！支持动态工作流与平价极速模式

2026年5月29日 | 3 分钟阅读
#claude#dynamic-workflows#claude-code#agent-architecture

Anthropic 近日正式发布了 #Claude Opus 4.8，并同步推出了两项重磅的 Claude Code 更新。其中最核心的新功能是“动态工作流”（Dynamic Workflows），该技术能够在大规模场景下并行运行多个子 Agent。此外，极速模式（Fast mode）也已支持 Opus 4.8，并提供了更低的价格。目前这两项功能均作为研究预览版（Research Previews）开放。

所谓的动态工作流，本质上是一个用于大规模协调子 Agent 的 JavaScript 脚本。Claude 会根据你描述的任务自动编写该脚本，并在后台由运行时（Runtime）执行。这使得用户的会话在 Agent 运行期间能保持即时响应。与传统的子 Agent 或技能（Skills）不同，动态工作流将执行计划转化为代码，而不是堆积在 Claude 的上下文窗口中，中间结果存储在脚本变量里，Claude 的上下文仅保留最终答案。这是该技术最核心的差异化优势。

该功能需要 Claude Code v2.1.154 或更高版本支持，可在 CLI（命令行）、桌面端和 VS Code 插件中运行。该功能向 Max、Team 和 Enterprise 会员开放，其中 Max 和 Team 账户默认开启，Enterprise 账户则需要管理员启用。此外，该功能也已同步上线 Claude API、Amazon Bedrock、Vertex AI 和 Microsoft Foundry。

用户可以通过两种方式启动工作流：在 Prompt 的任意位置加入“workflow”一词，或者开启名为“ultracode”的设置。Ultracode 结合了极高的推理能力（xhigh reasoning effort）与自动工作流编排。同时，Claude Code 还内置了“/deep-research”这一开箱即用的工作流。

在工作流运行期间，Claude 会根据提示词进行动态规划，将任务拆解为子任务，并在并行运行的多个子 Agent 之间分发。Agent 们会从独立的角度审视问题，随后由其他 Agent 对这些发现进行反驳和验证，整个过程不断迭代直至答案收敛。所有结果在被合并前都会经过严格检查。运行时拥有硬性限制：最多支持 16 个并发 Agent，单次运行总计上限为 1000 个 Agent。工作流脚本本身无法接触文件系统或 Shell，只有 Agent 能够读取、写入并运行指令。

工作流在执行过程中会实时保存进度。即使任务中断，也能够在同一会话中恢复，已完成的 Agent 会在恢复时直接返回缓存结果。由于协调工作在对话之外进行，整个规划始终能保持在正轨上。Anthropic 官方展示了一个重大案例：Jarred Sumner 利用动态工作流成功将 Bun 从 Zig 语言移植到了 Rust。该项目通过了 99.8% 的现有测试套件，生成了约 75 万行 Rust 代码，从首次提交到合并仅耗时 11 天。此外，极速模式（Fast mode）并非新模型，而是 Claude Opus 的高速配置，能提供 2.5 倍的输出 Token 速度，且模型智能度不打折扣，可通过 /fast 指令切换。

AgentUpdate 深度解析

Anthropic 的“动态工作流”是对传统 Multi-Agent 架构（如 AutoGen）的一次降维打击。以往框架将路由状态堆积在 LLM 上下文中，易导致上下文膨胀和幻觉。而 Claude 4.8 通过“大模型写 JS 脚本、运行时控制状态”的思路，将推理与执行彻底解耦，用代码变量存储中间态。这种大模型生成控制逻辑、编译器并行执行（上限 1000 个 Agent）的范式，攻克了多 Agent 扩展性与成本的瓶颈。这预示着 AI Agent 将从脆弱的 Prompt 管道走向高鲁棒性、自容错的工程化自主生产线。
