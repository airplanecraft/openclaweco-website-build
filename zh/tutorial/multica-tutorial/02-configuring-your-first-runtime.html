第 2 期: 激活守护进程与配置 Runtime

3 分钟阅读 | 更新于：2026-06-16

你可能有一个疑问：我的 Web 页面只负责把工单分配给 AI，可是实际上如果这个任务需要分析一个大型的代码仓库，云端的沙盒里根本没有我那“几兆的代码资产”，怎么玩？

这就牵扯出了 Multica 的核心逻辑层设计—— Runtime (运算节点)。

什么是 Runtime？

在管理版图里，Runtime 可以被视为每一个 AI 同事的办公桌。在你的电脑上启动 Runtime，你的电脑就会变成一个运算节点，AI 接到分配的活儿，就会来这个节点读代码、写文件、执行 Shell 代码测试。

启动你的本地 Daemon 守护进程

我们已经在上一节配置了 CLI 环境并完成了 Login，现在我们需要让电脑变为线上环境的肉鸡引擎。

很简单：开启守护进程！

multica daemon start

当终端出现不断回显的心跳连接日志时，说明你的 Daemon 已经活了，并且正和 Multica WebSocket 握手成功。 此时你的 Daemon 还会干一件非常有意思的工作：自动探测引擎接口。 它会全量扫描系统环境变量 $PATH 里是否带有 claude 或者 codex 原生指令链！

[!NOTE] 如果你的系统里刚刚配置好了 Claude Code 并且已经拿到了大模型额度，此处 Daemon 一定会汇报：Discovered compatible engine: claude.

检查配置态

不要关掉刚才运行 daemon start 的终端（或者是你可以在后台借助 tmux / nohup 跑），现在请回到 multica.ai 网页应用中。

  1. 展开页面边缘导航栏，进入 Settings 控制面板。
  2. 找到 Runtimes 监控状态卡片。
  3. 观察里面是不是赫然出现了一个处于 🟢 Online 绿灯的记录，其名字往往是你的电脑 Hostname 或者是刚刚探测到的注册身份！

如果是的，完美！你的本地环境已经安全上云了。任何派发给指定节点的工作，都将会在本地的极度隔离的安全域内自动闭环执行。下一步，让我们创造你的第一位虚拟同事。
