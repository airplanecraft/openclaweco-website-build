第 13 章 | 产品经理的新技能：从 PRD 到可运行原型只需 20 分钟

11 分钟阅读 | 更新于：2026-06-16

🎯 学习目标

学完本期你将掌握：

  1. 如何将产品需求文档 (PRD) 直接交给 Claude Code 生成可运行原型
  2. PM 不写代码也能驱动 Agent 完成从设计到部署的全流程
  3. 原型迭代的高效 Prompt 模板
  4. 快速验证想法的最佳实践

📖 核心概念讲解

13.1 PM 使用 Claude Code 的新范式

传统流程（2-4 周）:
  PM 写 PRD → 设计师画原型 → 前端排期 →
  开发 → 联调 → 交付

Claude Code 流程（20 分钟）:
  PM 粘贴 PRD → Claude 生成可运行原型 →
  PM 直接在浏览器中体验 → 口头反馈调整 → 完成

关键转变:
  ❌ PM 不需要学 React / Vue / CSS
  ✅ PM 需要学会描述清楚自己想要什么
  ✅ PM 需要学会用 Claude Code 进行迭代

13.2 PRD 到原型的转化因素

PRD 质量 原型产出 迭代次数
模糊描述（"做个管理后台"） 通用模板，需大量修改 10+ 轮
带功能列表 基本可用的原型 5-8 轮
带功能+用户故事+数据结构 高度匹配需求 2-3 轮
完整 PRD + 竞品截图 几乎不需修改 0-1 轮

13.3 PM 友好的指令模板

一份好的 PM → Claude 指令包含:

┌─────────────────────────────────────────────┐
│  1. 项目概述（一句话说清做什么）            │
│  2. 核心用户故事（3-5 个 As...I want...）  │
│  3. 页面列表（首页、列表页、详情页...）    │
│  4. 数据实体（用户、订单、商品...）         │
│  5. 技术偏好（React? Vue? 不在乎?）        │
│  6. 样式偏好（暗色主题? 类似 Notion?）      │
└─────────────────────────────────────────────┘

💻 模拟 Claude TUI 交互

场景：20 分钟从 PRD 到可运行原型

> 我是产品经理，请帮我把以下 PRD 做成可运行原型：

  ## 项目：团队 OKR 追踪工具
  ## 核心功能：
  1. 管理者可以创建季度 OKR
  2. 每个 Objective 下有多个 Key Results
  3. 团队成员可以更新 KR 的进度（0-100%）
  4. 首页仪表盘展示整体完成率
  ## 数据实体：Team, Objective, KeyResult
  ## 风格：类似 Linear，现代暗色主题

  包含用户名、公司、创建日期"

claude "把项目部署到 Vercel，生成一个可分享的 URL"

🔧 涉及的 Tools

工具 PM 视角用途 说明
Bash 项目创建与部署 执行 npx、npm 命令
Write 生成页面和组件 创建 React/Vue 文件
Edit 迭代修改 根据 PM 反馈调整 UI
Read 读取 PRD 解析需求文档
Bash 运行 dev server 启动本地预览

📝 本期要点回顾

  1. PM 不需要写代码，描述清楚需求 是最核心的技能
  2. PRD 越详细，原型 匹配度越高，迭代轮次越少
  3. 用 口语化指令 迭代原型，像和设计师对话一样自然
  4. 竞品截图 + 功能描述 = 最高效的原型生成输入
  5. Claude Code 让 PM → 可运行原型 的时间从 周级降到分钟级
