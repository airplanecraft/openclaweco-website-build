Chapter 03 | Understanding the Underlying Trust Model of Claude Code

15 MIN READ | UPDATED: 2026-06-16

🎯 Learning Objectives

By the end of this issue, you will understand:

  1. Claude Code's permission layering mechanism (Plan / Default / Auto / BypassPermissions)
  2. Which operations require user confirmation and which are automatically approved
  3. How to configure custom permission rules to protect sensitive files

📖 Core Concepts Explained

3.1 Four Permission Modes

Claude Code controls the AI's behavioral boundaries through Permission Modes:

╭─ Permission Mode Comparison ────────────────────────╮
│                                                      │
│  🔒 Plan Mode        Read-only analysis, no file modification        │
│  ├── Available Tools: Read, Glob, Grep, WebFetch           │
│  └── Unavailable: Write, Edit, Bash, Git                 │
│                                                      │
│  🔐 Default Mode     Read, write, execute; sensitive operations require confirmation        │
│  ├── Auto-approved: Read, Glob, Grep                     │
│  └── Requires confirmation: Write, Edit, Bash                      │
│                                                      │
│  ⚡ Auto Mode        Automatically approved based on preset rules             │
│  ├── User-defined allowlist                              │
│  └── Operations not on the list still require confirmation                            │
│                                                      │
│  ⚠️ BypassPermissions Skips all permission checks               │
│  ├── All operations execute automatically                                │
│  └── Only for trusted environments like CI/CD                         │
│                                                      │
╰──────────────────────────────────────────────────────╯

📚 Official Documentation Reference: Permission Modes

3.2 Tool Permission Categories

Each Tool has clear permission requirements:

Permission Level Tool Description
No Confirmation Needed Read, Glob, Grep, LS, WebFetch Read-only operations, safe
Requires User Confirmation Write, Edit, Bash, NotebookEdit Modifies files or executes commands
Special Permissions EnterWorktree, CronCreate Creates worktrees or scheduled tasks

3.3 Custom Permission Rules

Configured via .claude/settings.json or user global ~/.claude/settings.json:

{
  "permissions": {
    "allow": [
      "Bash(npm test)",
      "Bash(npm run lint)",
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(git log *)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(sudo *)",
      "Bash(curl * | bash)"
    ]
  }
}

Rule Syntax:

  • Bash(npm test) — Exact match
  • Bash(git *) — Wildcard matches all git subcommands
  • Write(src/**) — Only allows writing to the src directory
  • Edit(*.config.*) — Prohibits editing configuration files

  ]

🔧 Involved Tools / CLI

Tool/Command Purpose
Shift+Tab Switch permission mode within the terminal
claude --permission-mode plan Specify Plan Mode at startup
claude --permission-mode auto Specify Auto Mode at startup
/permissions View current permission rules in session
claude auto-mode defaults View/export Auto Mode rules
.claude/settings.json Project-level permission configuration
~/.claude/settings.json Global permission configuration

📝 Key Takeaways from this Issue

  1. Claude Code has four permission modes: Plan, Default, Auto, BypassPermissions
  2. Read-type tools (Read, Glob, Grep) are automatically approved by default
  3. Write/execute-type tools (Write, Edit, Bash) require user confirmation
  4. Use .claude/settings.json to fine-tune permission rules for each tool
  5. Plan Mode is the safe starting point for unfamiliar codebases — analyze first, then act
