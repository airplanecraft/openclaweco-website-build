Chapter 09 | Precise Prompt Scoping (Scope Boundary Control)

13 MIN READ | UPDATED: 2026-06-16

🎯 Learning Objectives

By the end of this issue, you will master:

  1. Why Claude sometimes "oversteps" and modifies unrelated code
  2. How to constrain modification scope using file paths and directory limitations
  3. Advanced usage of Subagent scope isolation
  4. Precise control with --allowedTools / --disallowedTools

📖 Core Concepts Explained

9.1 Problem: Why does Claude "overstep"?

When you say "fix this bug", Claude might:

  • ✅ Modify the target file ← Expected behavior
  • ❌ "Optimize" other unrelated files along the way ← Overstepping
  • ❌ Refactor modules you didn't mention ← Overconfidence

This is because Claude defaults to having read/write access to the entire project. Without explicit boundary instructions, it might "mean well but do harm".

9.2 Three-Layer Scoping Control Method

┌─ Layer 1: Prompt Level ─────────────────────────┐
│  "Only modify src/auth/login.ts, do not touch other files" │
│  → Simplest, suitable for one-time instructions        │
├─ Layer 2: Settings Level ──────────────────────── │
│  .claude/settings.json → permissions.deny       │
│  → Persistent protection, suitable for team sharing      │
├─ Layer 3: CLI Level ───────────────────────────── │
│  --allowedTools "Read" "Edit(src/auth/**)"      │
│  → Limited at startup, suitable for scripting        │
└──────────────────────────────────────────────────┘

💻 Code Demo: CLI Level Precise Control

# Chapter 9: Only allow reading and editing the src/auth/ directory
claude --allowedTools "Read" "Glob" "Grep" "Edit(src/auth/**)"

# Chapter 9: Forbid executing any bash commands (pure edit mode)
claude --disallowedTools "Bash"

# Chapter 9: Limit tools + limit turns (secure execution in CI/CD)
claude -p \
  --allowedTools "Read" "Glob" "Grep" \
  --max-turns 5 \
  "Review the security of the src/payment/ directory"

# Chapter 9: Only allow executing specific bash commands
claude --allowedTools \
  "Read" "Glob" "Grep" \
  "Bash(npm test *)" \
  "Bash(npm run lint)"

Settings File Level Protection

// .claude/settings.json — Project level
{
  "permissions": {
    "deny": [
      "Write(.env*)",
      "Edit(.env*)",
      "Write(prisma/migrations/**)",
      "Edit(prisma/migrations/**)",
      "Bash(rm -rf *)",
      "Bash(DROP *)",
      "Bash(sudo *)"
    ]
  }
}

💡 Prompt Scoping Quick Reference

❌ Vague Instructions (Prone to Overstepping):
  "Fix login bug"
  "Optimize performance"
  "Add error handling"

✅ Precise Instructions (Clear Scope):
  "Fix missing await for bcrypt.compare on line 34 in src/auth/login.ts"
  "Only optimize database query performance in src/api/search.ts, do not modify other files"
  "Add try-catch to the createOrder function in src/routes/payment.ts"

🔧 Involved CLI Flags

Flag Purpose Example
--allowedTools Whitelist to limit available tools "Read" "Edit(src/**)"
--disallowedTools Blacklist to disable tools "Bash" "Write"
--max-turns Limit maximum execution turns --max-turns 3
--add-dir Add additional directory access --add-dir ../shared

📝 Key Takeaways from this Issue

  1. Claude defaults to read/write access for the entire project, requiring active scope limitation
  2. Prompt Level: Directly state "only modify X file" in the instruction
  3. Settings Level: Use permissions.deny to protect sensitive files
  4. CLI Level: Use --allowedTools for whitelist restrictions
  5. Core of a good Prompt: Specific filename + Specific action + Clear boundaries
