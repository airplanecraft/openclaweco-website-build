第 5 期: 复用技能池 (Skills) 与内网私有部署 (Self-Hosting)

3 MIN READ | UPDATED: 2026-06-16

[Translation Pending]\n\n当我们在用传统的 Prompt 窗对着 AI 进行来回沟通时，所有关于这批代码库环境上下文的心血，常常在关掉浏览器或刷新的一瞬间付诸东流。 但 Multica 在高阶玩法引出了一道大招—— Skills (原子技能固化)！而且它的极客扩展极大地支持私有化部署。

在这最后一集中，我们来聚焦一下这些进阶用法。

技能池 (Reusable Skills)：沉淀才是最好的成长

如果你的下属解决了一次“旧版 Django 跨域故障”，下一次再碰到一样的问题你还要重新向新同事辅导一遍，那真的是非常蠢的项目管理。对于 Multica 里的 Agent，这一问题迎刃而解！

当一场错综复杂、耗费大量试错精步解决后的工单最终转为 “Completed” 状态时，它的解题思路就可以直接固化成一个可以被所有其他 Agent 重复调用的 Skill 。

你可以将其理解为一个“组织内的补丁智库”。比如，你把这种重构代码的过程封装成了技能后分配给另一个萌新机器人，该机器人瞬间就拥有了处理同源问题的绝对先验知识！随着时间的推波助澜，你的 AI 小军团的能力池会实现真正的几何体递增速（Compound Knowledge）提升。

高隐私要求的 Self-Hosting （Docker 私有部署） 🐳

我们把 Runtime 挂件丢在了本机跑沙盒，但由于任务委派看板的指令调度目前还在 Multica Cloud 云平台上，对由于高度保密的项目组或许是一个隐患。 Multica 因为其完备开源的基因，完全支持离线服务器自主接管！ 只需要一台干净的可视机和容器支持。

一键启航指令配置：

从头搞起私有化：

git clone https://github.com/multica-ai/multica.git
cd multica

# 设置基础机密变量 （特别是务必把 JWT_SECRET 改了）
cp .env.example .env

# 通过 Docker 唤起
docker compose up -d

构建内置引擎

引擎组跑起来后，还需要对 PostgreSQL 数据字典跑一下 Schema 推移：

cd server 
go run ./cmd/migrate up 
cd ..
make start

这时候你的前端 (Next.js) 面板和底层架构调度（Go + WS 服务端）就会在你绝对控盘隔离的企业级虚拟机里进行自我闭环。 通过配置你专属云上的 Multica CLI 发起指令交互，让它彻底变身为专供贵小组私人调遣的黑盒机器人同事团队。

至此，恭喜你已经彻底通关所有 Multica 精髓部分，火速去分配你的第一张真人工单吧！🎊
