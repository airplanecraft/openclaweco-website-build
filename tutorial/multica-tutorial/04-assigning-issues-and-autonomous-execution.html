第 4 期: 分配 Issue! 感受全自动工单的震撼

3 MIN READ|UPDATED: 2026-06-16

[Translation Pending]\n\n各位同学！激动人心的时刻终于来了。前置的架构都已经组装完毕：平台 -> 同事 -> 设备。 现在我们要给这位新朋友发配任务了！这就需要进入协同开发的最常见动作——指派 Issue。

零门槛发布悬赏

在系统中向 AI 分配任务可以完全对齐 JIRA 这些工具的操作感。你有两种核心的方法发起行动。

途径一：基于 Web 看板图形化派发

进入云端界面的主面板，点击左边最粗壮那个加号创建一个 Issue： 在这里你要填写两样关键事务：

  • 目标（Goal)：比如 “重构 pages/api.ts 支持跨域鉴权，并在 logs 目录写下报错原因日志”。
  • 指派给 (Assignee)：在这个下拉菜单中，选取我们上节课培训的 Fullstack Alex 大将！

点击创建。你可以瞬间看到任务的流转：Alex 的状态立刻变成工作态。

途径二：完全基于 CLI 的极客手段

如果你极度厌弃来回切屏，请直接在你的本地开发目录打开终端：

# 在此目录丢一枚工单上天
multica issue create

系统会通过简单的交互式问答或者后缀补充把你的任务目标直达天庭。

What's actually happening？

在这个过程之中，Multica 会做如下一套全自动的运转：

  1. Enqueue: 把该任务塞入队列平台。
  2. Claim: 如果 Alex 当前没干别的活，他会立刻抢走单子。
  3. Start (核心!): Multica 向对应的本地 Daemon Runtime 广播通讯！在你的本地电脑上瞬间唤起一个沙盒。
  4. Execution: 开始借调你的 Claude Code 执行目标。甚至因为底座赋予能力，若碰到了 TypeError，Alex 会在看板底下追评：“遇到了阻碍了，缺乏 Types 定义... 我等一下去修复...”。
  5. Real-time Status: 所有的终端进展会借助 WebSocket 推回到云端，让你在吃薯片时实时用手机看到进度流！

坐等单据变成 Complete! 🎉 就是这个产品的核心爽感！
