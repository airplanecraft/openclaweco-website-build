第 3 期: 创造你的 AI 同事：Agents 的生命周期

3 MIN READ | UPDATED: 2026-06-16

[Translation Pending]\n\n在上两节课中，我们部署了地基：一个坚实的管理账号和一个可靠运行的后端本地守护环境（Runtime）。 在这一期，我们要在架构上注入灵魂——那就是配置具备独立身份的 Agent (AI 同工)！

为什么叫它“同事”？

因为在 Multica 的架构设计范内，你可以拥有很多个 Agent。 比如你可以创建一个专攻 “后端 API 以及数据库 SQL ”优化的老手 Database Expert 01，也可以创建一个专攻前台 UI 的 Frontend Trainee。 他们会在同一个看板下同屏存在，有自己的专属头像和任务接单队列。

Let's Create!

回到主系统：

  1. 点击导航栏的 Settings -> Agents -> New Agent。
  2. 配置基本信息：
    • 名字：例如可以取名叫"Fullstack Alex"
    • 平台载体 (Provider)：这取决于你的 Runtime。如果你安装了 Claude Code，你可以在底座提供方这里选中 Claude。系统内置了对其底座能力的对接！
  3. 分配归宿： 把你刚刚新建的 Agent 关联到前置课程里配置的属于你的设备环境 Runtime 里！ 这个动作的含义极为关键：以后分配给 “Alex 工程师”的工单，系统通通都会远程推送到你桌面上的那台运行着 Daemon 进程的电脑里！

多空间隔离 (Workspace)

如果你的实际项目非常复杂（例如一半业务在搞移动端 Swift 开发，一半在搞内部运维系统 Rust），让 Alex 经常窜行于不同语言堆内非常容易引起他大模型记忆栈中的污染。

Multica 给出的解决方案是纯粹的物理隔离：Multi-Workspace 你可以为主页面建立多个 Workspace。每一个空间是一条完全独立的河流，具有独立的人员配备、独立的技能沉淀！这就和企业里面的各种事业部是完全一个逻辑的。

配置好心仪的虚拟员工后，我们就可以在第 4 课进行第一次震撼的发包实践了。
