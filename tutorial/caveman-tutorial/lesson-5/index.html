📖 Core Content

5.1 Skill File Structure

Caveman's core Skill is located in the repository's skills/caveman/ directory. As a Claude Code Skill, it is essentially a Markdown file (SKILL.md) containing complete behavioral instructions.

caveman/
├── skills/
│   ├── caveman/           ← Main Skill
│   │   └── SKILL.md       ← Core Rule Definition
│   ├── caveman-commit/    ← Git Commit Skill
│   │   └── SKILL.md
│   ├── caveman-review/    ← Code Review Skill
│   │   └── SKILL.md
│   ├── caveman-help/      ← Help Info Skill
│   │   └── SKILL.md
│   └── compress/          ← Compression Skill
│       └── SKILL.md
├── hooks/                 ← Hook Scripts
├── commands/              ← Command Definitions
└── plugins/caveman/       ← Plugin Packaging

When you type /caveman, the Agent loads the rules from SKILL.md and immediately applies them to the current session.

5.2 Caveman Core Instructions

The following core behavioral rules are defined in SKILL.md (simplified version):

## Caveman Communication Rules

1. **Terse like caveman** — Technical substance exact. Only fluff die.
2. **Drop** — articles, filler (just/really/basically), pleasantries, hedging
3. **Fragments OK** — Complete sentences not required
4. **Short synonyms** — Use shortest word that conveys same meaning
5. **Code unchanged** — Never compress code blocks, commands, or file paths
6. **Pattern** — [thing] [action] [reason]. [next step].
7. **Persistence** — ACTIVE EVERY RESPONSE. No revert after many turns.
8. **Exit** — "stop caveman" or "normal mode" to deactivate

💡 Important: Rule 5 is key to Caveman not compromising technical accuracy—all code, commands, and file paths remain unchanged; only natural language descriptions are compressed.

Decomposition example:

Original Question: "Why did my Docker container exit immediately after starting?"

Caveman Answer:

💻 Three Practical Scenarios

Scenario 1: Node.js Memory Leak Debugging

Your Question:

My Node.js Express server's memory increased from 100MB to 2GB after running for 48 hours. How do I troubleshoot this?

🗣️ Normal Claude Answer (~180 tokens):

This sounds like a classic memory leak issue in a Node.js application. 
Here are several approaches you can use to diagnose the problem:

1. First, I'd recommend using the built-in Node.js inspector with the 
   --inspect flag...
2. You could also try using the heapdump module to take heap snapshots...
3. Another useful tool is clinic.js which provides...
4. Make sure to check for common patterns that cause leaks...
   ...(continues with detailed explanations for each step)

🪨 Caveman Answer (~45 tokens):

Classic leak pattern. Debug steps:

1. `node --inspect server.js` → Chrome DevTools → Memory tab
2. Heap snapshot at start, snapshot at +2h, compare
3. Look for: growing arrays, unclosed event listeners, global caches

Common Express culprits:
- `app.use()` middleware storing req refs
- Session store without TTL
- Socket.io connections not cleaned on disconnect

Quick win: `process.memoryUsage()` logged every 5min → find growth rate.

Note: Code commands and technical terms are fully preserved; only narrative fluff is removed.

Scenario 2: TypeScript Generics Explanation

Your Question:

Explain Conditional Types in TypeScript

🪨 Caveman Answer:

Conditional Types = type-level ternary expression.

Syntax: `T extends U ? X : Y`

Practical example:
```typescript
type IsString<T> = T extends string ? "yes" : "no";

type A = IsString<"hello">;  // "yes"
type B = IsString<42>;       // "no"

Distributive behavior: union automatically expands.

type ToArray<T> = T extends any ? T[] : never;
type R = ToArray<string | number>;  // string[] | number[]

Built-in conditional types: Exclude<T,U>, Extract<T,U>, NonNullable<T>, ReturnType<T>.


### Scenario 3: Code Refactoring Suggestions

**Your Question:**

This function is too long, help me refactor it: function processOrder(order) { // Validate order... (20 lines) // Calculate price... (30 lines)
// Send notification... (15 lines) // Update database... (25 lines) }


**🪨 Caveman Answer:**

Split into 4 single-responsibility functions:

async function processOrder(order: Order): Promise<Result> {
  const validated = validateOrder(order);       // Validate
  const priced = calculatePrice(validated);     // Price
  await persistOrder(priced);                   // Persist
  await notifyStakeholders(priced);             // Notify
  return { success: true, orderId: priced.id };
}

Principle: Each function ≤ 20 lines, single responsibility, independently testable. Error handling: Each function throws independently, processOrder top-level try/catch.
